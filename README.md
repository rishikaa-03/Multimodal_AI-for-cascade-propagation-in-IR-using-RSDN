**Multimodal AI for Cascade Propagation and Cross-Zone Frontier Detection**
**Using Rolling Stock Dependency Graphs in Indian Railways**

## What this is (and isn't)

This project is a **research/academic prototype built entirely on synthetic
simulation data** — not a live operational system connected to Indian Railways.
That distinction is stated here up front rather than left to be discovered:

- There is no public, free, key-less API for live Indian Railways running
  status (NTES supports single-train passenger lookups only). Third-party
  "live train status" feeds are unofficial scrapes against NTES's terms of
  service, so this project does not use them.
- All delay events, cause labels, and rolling-stock chains are generated by
  the project's own SimPy-based cascade simulator — they are not scraped or
  sourced from real IR operational history.
- Model accuracy figures describe how well each model fits this synthetic
  simulation, not real-world predictive performance. Cause-classification
  accuracy in particular is inflated by templated synthetic text and should
  be read as a demonstration of pipeline correctness, not generalizable NLP
  performance.

## Key Features

| Feature | What it does |
|---|---|
| **Multiplex railway network graph** | Stations and trains modeled as a weighted graph with three dependency layers: Infrastructure (`INFRA`), Schedule Dependency (`SCHED_DEP`), Rolling Stock Dependency (`RS_DEP`) |
| **Discrete-event cascade simulation** | Delay propagation traced through the network using weighted BFS, orchestrated by a SimPy discrete-event engine |
| **Cause prediction** | TF-IDF + Logistic Regression / Random Forest pipeline classifies free-text delay reports into cause categories |
| **Cascade impact prediction** | GATv2 graph neural network (PyTorch Geometric) estimates downstream cascade depth and magnitude |
| **Cross-Zone Cascade Frontier Detector** | Computes a crossing probability at every zone-boundary station, raises an alert past a calibrated threshold |
| **Mitigation recommendations** | Rule-based engine tests dependency-breaking actions (holds, reroutes, rolling-stock decoupling) and ranks them by estimated delay recovery |
| **Interactive dashboard** | Streamlit + Plotly, free OpenStreetMap tiles (no API key), live network map and event-driven simulation view |

## Tech Stack

| Layer | Tool |
|---|---|
| Graph modeling | NetworkX |
| Discrete-event simulation | SimPy |
| Classical ML | scikit-learn (TF-IDF, Logistic Regression, Random Forest) |
| Graph neural network | PyTorch Geometric (GATv2) |
| Dashboard | Streamlit, Plotly, OpenStreetMap tiles |
| Storage | SQLite |
| Language | Python 3 |

> Every tool in this stack is free, open-source, and requires no subscription
> or API key — a hard constraint of the project.

## Getting Started

<details>
<summary><strong>1. Prerequisites</strong></summary>

- Python 3.10+
- pip

</details>

<details>
<summary><strong>2. Installation</strong></summary>

```bash
git clone <this-repo-url>
cd RailwayCascadeAI
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

</details>

<details>
<summary><strong>3. Generate the dataset and training artifacts</strong></summary>

If the `.pkl` artifacts and `data/*.csv` files aren't already present, run
the module pipeline in order:

1. Simulate the synthetic dataset 
2. Build the multiplex graph 
3. Run the cascade simulator to generate training data 
4. Train the cause classifier and cascade predictor 
5. Calibrate the frontier detector 
6. Generate the whole-network risk summary 

</details>

<details open>
<summary><strong>4. Run the dashboard</strong></summary>

```bash
cd graph
streamlit run app.py
```

The app opens at `http://localhost:8501`.

</details>
